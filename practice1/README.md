# Практика 1. Архитектурное проектирование с ИИ в нотации C4

## Цель работы (по методичке)

1. Освоить уровни C4: Context (C1), Container (C2), Component (C3).
2. Сформулировать Problem Statement для предметной области.
3. Сгенерировать диаграммы с помощью ИИ и выполнить ручную доработку.
4. Зафиксировать итоговые артефакты и критический анализ результата.

## Выбранная тема

Веб-приложение для бронирования переговорок в компании.

## Problem Statement

Компания нуждается в веб-приложении для бронирования переговорных комнат сотрудниками и офис-администраторами.  
Пользователь должен находить свободные переговорки по времени, вместимости и оборудованию, а затем создавать бронирование.  
Организатор встречи должен иметь возможность найти существующих пользователей системы по email, добавить их к брони и направить приглашение на почту.  
Система обязана предотвращать пересечения бронирований и хранить историю для аналитики загрузки помещений.  
Решение интегрируется с корпоративной системой аутентификации и внешним сервисом уведомлений.

## Ход работы

### Шаг 1. Постановка задачи

Определены:
- роли пользователей (`Сотрудник`, `Офис-администратор`);
- основные функции (поиск свободных комнат, создание/просмотр броней);
- внешние системы (в постановке — корпоративный SSO и сервис уведомлений; в MVP practice2 — вход по email/паролю и JWT, приглашения участников по SMTP при настройке почты).

### Шаг 2. Генерация C1 (Context)

- Сгенерирован и доработан код диаграммы: `diagrams/context.puml`.
- Уточнены внешние системы и типы связей; контекст приведён к фактическому стеку practice2 (JWT, SMTP для приглашений участников, без отдельного блока SSO на диаграмме).

### Шаг 3. Генерация C2 (Container)

- Сгенерирован и доработан код диаграммы: `diagrams/container.puml`.
- Выделены контейнеры: Web UI, API Gateway, Booking Service, PostgreSQL, Redis.

### Шаг 4. Генерация C3 (Component)

- Выбран ключевой контейнер: `Booking Service`.
- Сгенерирован и доработан код диаграммы: `diagrams/component.puml`.
- Определены компоненты: Router, Security (JWT), Service, Repository, Cache Adapter, Metrics Exporter.

### Шаг 5. Критическая проверка

Проверены:
- корректность нотации C4;
- реалистичность связей;
- наличие ролей и протоколов взаимодействия;
- отсутствие «галлюцинаций» ИИ.

## Артефакты практики

- Исходники PlantUML:
  - `diagrams/context.puml`
  - `diagrams/container.puml`
  - `diagrams/component.puml`
- PNG при необходимости собираются локально, например: `plantuml diagrams/*.puml` (файлы `.png` в репозиторий не включались).
